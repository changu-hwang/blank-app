# grill-with-docs — 문서 대조 집요 검증

grill-me의 질문 방식에 **문서 대조**를 더한 스킬이다. 사용자의 답변과 문서 내용이 일치하는지, 문서 자체에 빠진 것이나 서로 어긋나는 것이 없는지를 따진다.

검증 대상 문서: $ARGUMENTS

## 0. 준비 (질문 전에 반드시)

1. 지정한 문서를 모두 읽는다. 경로가 없거나 파일이 없으면 **멈추고** 올바른 경로를 묻는다. 추측으로 진행하지 않는다.
   - .hwp/.hwpx/.pdf/.docx는 kordoc·hwpx·pdf·docx 스킬로 텍스트를 추출한다.
2. 문서 구조를 표로 요약해 보여준다: 장·절 목록, 핵심 수치·기준, 참조하는 외부 규정.
3. 검증 기준 문서가 함께 있으면(과업지시서, RFP, 작업규정 등) 무엇이 **기준**이고 무엇이 **검증 대상**인지 사용자에게 확인받는다.

## 1. 문서 자체 점검 (질문 목록 만들기)

질문하기 전에 아래 항목을 찾아 목록으로 만든다. 각 항목에 문서 위치(장·절·쪽 또는 줄)를 붙인다.

| 유형 | 찾을 것 |
|---|---|
| 누락 | 기준 문서(과업지시서·RFP)가 요구했는데 설계서에 없는 항목 |
| 모순 | 같은 문서나 문서끼리 수치·용어·일정이 서로 다른 곳 |
| 모호 | "적절히", "필요시", "충분히"처럼 측정할 수 없는 표현 |
| 근거 부족 | 수치·기준을 쓰고 출처(규정·지침·시험성적서)를 밝히지 않은 곳 |
| 시점 | 폐지·개정된 규정 인용 가능성 [확인필요] |

## 2. 질문 진행 규칙

1. **한 번에 질문 하나.** 영향이 큰 항목(누락·모순 → 근거 부족 → 모호 순)부터 묻는다.
2. **질문마다 문서 위치를 인용한다.** 예: "3.2절은 GSD 5cm, 4.1절 장비표는 8cm 촬영 기준입니다. 어느 쪽이 맞습니까?"
3. **답이 문서와 다르면 지적한다.** 사용자 답이 맞으면 문서 수정 필요로 기록한다.
4. 선택이 필요하면 대안 2~3개와 트레이드오프를 제시하고 사용자가 결정한다.
5. Claude가 덧붙이는 지식은 [사실]/[추정]/[의견]으로 구분하고, 확실하지 않은 수치·법규는 [확인필요]로 표시한다.
6. 공간정보·측량 문서면 grill-me의 "공간정보·측량 분야 단골 질문"도 함께 확인한다.
7. 사용자가 "그만", "정리해줘"라고 하면 즉시 종료하고 결과를 낸다.

## 3. 문서 수정

- 문서는 **사용자가 요청할 때만** 고친다. 기본은 수정안 제시까지다.
- 수정 요청이 있으면 확정된 결정만 반영하고, 바꾼 위치를 목록으로 알려준다.

## 4. 종료 시 산출물

| 구분 | 내용 |
|---|---|
| 문서 수정 필요 | 위치, 현재 내용, 수정안, 근거 |
| 확정된 결정 | 질문 과정에서 확정된 사항 |
| 미결 사항 | 답하지 못한 질문, 확인 주체·시점 |
| 리스크 | 리스크, 영향도(상/중/하), 대응 방안 |
| 기준 문서 대비 매핑 | (기준 문서가 있을 때) 요구사항별 반영 여부: 반영 / 일부 / 누락 |

두괄식으로 가장 심각한 누락·모순부터 쓴다.
