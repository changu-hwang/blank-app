# Claude Code 스킬 사용 가이드

> 기준: 2026-10-30, 이 계정의 Claude Code 세션에 설치된 스킬(각 `SKILL.md` 원문 확인 후 정리)
> 구성: 핵심 6개는 단계별 상세, 나머지는 호출 방법·입력·결과 요약

## 공통 사용법

| 방법 | 입력 예 | 언제 |
|---|---|---|
| 자연어 요청 | "이 RFP로 제안서 목차 짜줘" | 대부분. 요청이 스킬 설명과 맞으면 Claude가 자동으로 불러 씀 |
| 이름 지정 | "kordoc 스킬로 이 hwp 읽어줘" | 비슷한 스킬이 여러 개라 확실히 고르고 싶을 때 |
| 슬래시 명령 | `/code-review`, `/morning` | 명령형 스킬 |

**팁**: 파일(PDF·hwp·xlsx)을 첨부하거나 경로를 알려주면서 요청하면 정확도가 올라간다.

## Ⅰ. 핵심 스킬 상세

### ① proposal-writing-agent (제안서 작성)

작성자의 기존 제안서 방식(4파트 구조, Q&A 방식, 정량 차별화)을 반영한 스킬.

| 단계 | Claude가 하는 일 | 사용자가 할 일 |
|---|---|---|
| 0. 입력 | 사업명, 발주기관, 과업범위, 배점표, 제출형식, 기한 추출 | RFP·과업지시서와 기존 제안서 템플릿 첨부 |
| 1. 요구사항 분석 ⛔ | 배점표와 우선순위를 표로 제시하고 **멈춤** | 누락 항목과 우선순위 확인. 확인해야 다음 단계로 진행 |
| 2. 목차 설계 | 4파트(제안개요, 본과업, 사업관리, 지원방안)를 배점표와 1:1 매핑 | 목차 확정 |
| 3. 섹션 작성 | 평가위원 예상 질문 → 답변. 배점 큰 섹션부터 한 섹션씩 | 실제 실적 수치와 근거자료 제공 |
| 4. 형식 점검 | 격식체, 두괄식, 사실/추정 구분, 분량 | — |
| 5. 산출물 | docx 제안서 + 발표용 pptx, 배점 매핑표 별첨 | 형식 지정 |
| 6. 최종 검증 | 배점 누락 재점검, 차별화 요약, 리스크 지적 | 최종 검토 |

```
예) "첨부한 ○○시 지하시설물 DB구축 과업지시서로 기술제안서 작성해줘. 기존 템플릿은 2025년 △△사업 제안서야."
```

⚠️ 스킬 안의 예시 수치(탐지율 70%, ±50cm)는 예시일 뿐이다. 사업마다 실제 시험성적서나 실적 수치로 바꿔야 한다.

### ② hwpx (한글 문서 편집·자동화)

| 작업 | 요청 예 |
|---|---|
| 양식 채우기 | "이 신청서 hwpx에 회사정보 채워줘" (빈칸·표 셀을 라벨로 찾아 입력) |
| 서식 변경 | "줄간격 160%, 여백 20mm, 쪽번호 넣어줘" |
| 문서 생성 | "착수보고서를 공공기관 보고서 양식 hwpx로 만들어줘" |
| 비교 | "변경 전후 과업지시서 신구대조표 만들어줘" |
| 대량 생산 | "명단 엑셀로 수료증 30장 메일머지해줘" |
| 특수 문서 | 사진대지, 회의 명패, 조직도, 표 합계 계산 |

- 작동 방식: 문서 구조를 먼저 분석 → 좌표를 확정해 편집 → 결과 검증 순서로 진행하고, 원본은 보존한다.
- **.hwpx 전용**이다. .hwp는 한글에서 hwpx로 다시 저장한 뒤 사용하거나 kordoc을 쓴다.

### ③ kordoc (한국 공문서 툴킷)

| 기능 | 내용 | 요청 예 |
|---|---|---|
| 읽기 | hwp, hwpx, hml, PDF, DOCX, XLSX → Markdown | "이 hwp 과업지시서 내용 뽑아줘" |
| 생성 | Markdown → 공문서(기안문·보고서·계획서·통지·회의록 프리셋) | "이 내용으로 기안문 hwpx 만들어줘" |
| 서식 채우기 | 양식 자동 작성 | "입찰참가신청서 채워줘" |
| 편집 | 기존 문서 내용만 수정(구조 유지) | "3장 일정표만 수정해줘" |
| 직인 배치 | 도장·서명 이미지 위치 지정 | "직인 넣어줘" |
| 비교·검증 | 문서 비교, 미리보기 | "두 버전 비교해줘" |

**hwpx와 kordoc 구분**: .hwp(구버전) 읽기나 공문 새로 만들기 → kordoc, 기존 hwpx를 세밀하게 편집 → hwpx.

### ④ deep-research (심층 조사)

| 단계 | 내용 |
|---|---|
| 1 | 필요하면 범위를 묻는 확인 질문 |
| 2 | 질문을 하위 주제로 나눔 |
| 3 | 조사 에이전트 여러 개가 동시에 웹 조사 |
| 4 | 보고서 작성 에이전트가 출처를 붙여 종합 |
| 5 | 보고서 전달 |

```
예) "최근 3년 국토부·NGII 디지털트윈 발주사업 규모와 주요 수주사 조사해줘"
```

⚠️ 비용과 시간이 많이 드는 방식이라, 간단한 사실 확인에는 일반 질문이 낫다.

### ⑤ skill-creator (스킬 제작)

| 단계 | 내용 |
|---|---|
| 1. 의도 파악 | 무엇을, 언제 자동으로 실행할지 인터뷰 |
| 2. SKILL.md 작성 | 트리거 설명과 절차 작성 |
| 3. 테스트 | 테스트 사례로 실행해 평가 |
| 4. 개선 | 결과를 보고 수정 반복 |

```
예) "항공사진측량 성과검수(검사점 RMSE, 작업규정 허용오차 판정) 스킬 만들어줘"
```

### ⑥ xlsx / pptx / docx / pdf (오피스 파일)

| 스킬 | 할 수 있는 일 | 요청 예 |
|---|---|---|
| xlsx | 생성·편집, 수식, 차트, 지저분한 데이터 정리 | "측점 성과표 CSV를 엑셀로 정리하고 RMSE 수식 넣어줘" |
| pptx | 생성·편집, 내용 추출, 템플릿 적용 | "회사 템플릿으로 중간보고 발표자료 만들어줘" |
| docx | 생성·편집, 변경 내용 추적, 템플릿 | "제안서 docx로 출력해줘" |
| pdf | 추출, 병합, 분할, OCR, 양식 채우기 | "스캔 PDF를 OCR로 검색 가능하게 해줘" |

## Ⅱ. 기타 스킬 요약

### 데이터 분석 (`data:`)

| 스킬 | 입력 | 결과 | 요청 예 |
|---|---|---|---|
| analyze | 데이터 + 질문 | 분석 결과 | "사업별 수익률 비교해줘" |
| explore-data | CSV·표 | 품질 진단(결측·이상치) | "이 GCP 좌표 파일 점검해줘" |
| statistical-analysis | 수치 데이터 | 통계, 검정 | "두 장비 정확도 차이 유의한지 봐줘" |
| create-viz / data-visualization | 데이터 | 차트 이미지 | "오차 분포 그래프" |
| build-dashboard | 데이터 | HTML 대시보드 | "사업 진도 대시보드" |
| validate-data | 분석 결과 | 검증 의견 | "보고 전에 이 분석 검증해줘" |
| sql-queries / write-query | 테이블 정보 + 요구사항 | SQL | "PostGIS 버퍼 분석 쿼리" |
| data-context-extractor | DB 스키마 | 사내 데이터 전용 스킬 | — |

## 추천 조합

| 업무 | 스킬 순서 |
|---|---|
| 입찰 제안서 | kordoc(RFP 읽기) → proposal-writing-agent → hwpx/docx → pptx |
| 성과보고서 | xlsx(성과표) → data:statistical-analysis(정확도) → kordoc(보고서 생성) |
| 동향 보고 | deep-research → docs 또는 hwpx |

## 참고

- 설치된 스킬은 계정·플러그인 설정에 따라 바뀔 수 있다. 최신 목록은 Claude Code에서 `/`를 입력해 확인한다.
- 카파시 코딩 원칙은 스킬이 아니라 저장소 `CLAUDE.md`에 들어 있어 세션마다 자동 적용된다.
